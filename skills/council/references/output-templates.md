# Design content for option A

When the user chooses A, present the design for review in the conversation (and it is already on the workbench). Cover these sections; do not create markdown files.

1. **Selected design** — a short description.
2. **Architecture decisions** — topic, decision, reason, and which master raised it (layer boundary, data authority, invariant owner…).
3. **Rejected alternatives** — the other candidates and why they lost.
4. **Skeptic log** — stage, challenge, the masters' assessment, outcome (accepted / rejected with its legitimate reason / handled).
5. **Domain language** — term and meaning.
6. **Invariants** — numbered.
7. **Decision Table** — the final table.
8. **Legacy behavior deliberately replaced** — or 「無」; the Legacy Git Audit uses it.
9. **Acceptance scenarios** — one Given/When/Then per Rule.
10. **Accepted risks** and **Follow-up concerns**.
11. **Task plan** — per Task: number, title (Rule range and observable behavior), Rules covered, test layer, the goal (which observable behavior exists when it is done), and its test list.
